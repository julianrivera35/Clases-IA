02
Definición

¿Qué es vibe coding?

Andrej Karpathy, cofundador de OpenAI y exdirector de IA en Tesla, propuso el término en febrero de 2025 para una forma de programar en la que se describe lo que se necesita, se acepta el código que genera la IA y se revisa poco o nada. Es útil para prototipos rápidos. En un entorno institucional, el código generado necesita especificación, pruebas y revisión antes de usarse.

Vibe coding sin revisión

Se pide, se acepta el resultado y los errores se devuelven a la IA hasta que funcione. No hay revisión del código ni pruebas.

Uso: ideas rápidas y prototipos desechables.

Prototipado con verificación

Especificación, pruebas, revisión de seguridad, datos sintéticos y control de versiones.

Uso: herramientas internas sencillas, maquetas para validar con usuarios y pruebas de concepto.

Desarrollo con agentes

Agentes de código (Claude Code, GitHub Copilot en modo agente, Codex) que trabajan en un repositorio, ejecutan pruebas y proponen cambios que un humano revisa antes de integrarlos.

Uso: software que va a producción, con control de versiones, integración continua y revisión de código.

Lo que la IA hace bien

  • Pasar de una descripción a una interfaz que funciona en minutos.
  • Escribir el código repetitivo: formularios, tablas, filtros, exportar e importar.
  • Explicar código que no escribiste y proponer pruebas.

Dónde falla sin indicaciones

  • Agregar requisitos que nadie pidió y omitir otros.
  • Mostrar texto del usuario como HTML (XSS) o guardar secretos en el código.
  • Recomendar librerías que no existen o que no revisaste.

Lo que audita la persona

  • Decidir qué problema vale la pena resolver.
  • Definir qué significa "funciona" (criterios de aceptación).
  • Proteger los datos y decidir si el prototipo sigue adelante.

04
Un solo archivo, sin servidor

¿De qué está hecha una app de un solo archivo?

Lo que vamos a construir es un archivo .html que tiene adentro la estructura, el estilo y la lógica. Se abre con doble clic, funciona sin internet y guarda los datos solo en ese navegador. Toca cada capa.

Opción 1 · La de hoy

Doble clic

Guarda el archivo como mesa-solicitudes.html y ábrelo con Edge o Chrome. La dirección empieza por file://. Es suficiente para un prototipo.

Opción 2 · Si tienes Python

Servidor local

En la carpeta del archivo: python -m http.server 8000 y abre http://localhost:8000. Algunas funciones del navegador piden http y no file.

Opción 3 · Compartir

Publicarla

En OneDrive o SharePoint un .html normalmente se descarga en lugar de abrirse. Para compartir un prototipo se usa un sitio estático aprobado por TI, y nunca con datos reales.

05
El método del curso, aplicado a especificar software

TAREA para especificar software

Un buen prompt de código se parece más a una historia de usuario con criterios de aceptación que a una petición. Cada letra de TAREA responde a una pregunta que un desarrollador te haría antes de empezar.

T

Tarea principal

¿Qué app, para quién y qué problema resuelve? Una o dos frases con el contexto.

EjemploConstruye una app web de una sola página, "Mesa de Solicitudes", para el área administrativa. Hoy las solicitudes llegan por correo y Teams y nadie sabe cuáles están vencidas.
A

Acción esperada

Las funciones, numeradas y verificables. Cada una debe poder probarse con un sí o un no.

Ejemplo1. Radicar una solicitud con id automático. 2. Tablero por estado, con arrastrar y soltar. 3. Semáforo de vencimiento. 4. Filtros. 5. Cuatro indicadores. 6. Guardar en el navegador.
R

Rol del modelo

El tipo de desarrollador que quieres y en qué debe fijarse.

EjemploActúa como desarrollador front-end sénior que cuida la seguridad, la usabilidad y la accesibilidad.
E

Ejemplo de salida

El formato del entregable y el modelo de datos: campos, valores posibles y datos de ejemplo.

EjemploUn único archivo HTML con CSS y JS adentro. Campos: id, fecha_radicacion, solicitante, area, tipo… Plazos por tipo en días hábiles. Incluye 12 solicitudes de ejemplo inventadas.
A

Aclaraciones adicionales

Restricciones técnicas, de seguridad y de datos. Aquí van las restricciones que la IA no aplica por su cuenta.

EjemploSin librerías ni CDN. El texto del usuario se muestra como texto, nunca como HTML. Validar campos obligatorios. Nada de datos reales. Entrega el archivo completo en un solo bloque.

Iterar sin perder el control

El ciclo: especificar, generar, probar, mejorar

La primera versión casi nunca es la final. La calidad depende de cómo se itera: un cambio a la vez, con pruebas y guardando cada versión que funciona. Toca cada paso del ciclo.

08
El código generado también se audita

¿Es segura la app que escribió la IA?

Que una app funcione no quiere decir que sea segura. La IA aprendió de mucho código, también del inseguro, y repite los errores clásicos si no le pides lo contrario y si nadie revisa.

≈45 %de las tareas de desarrollo resueltas con código generado por IA introdujeron vulnerabilidades en estudios recientes.IBM Think, 2026
≈1 de 5paquetes recomendados por asistentes de IA no existe. Alguien puede registrarlos con malware: slopsquatting.TechTarget, 2026
74vulnerabilidades publicadas se rastrearon directamente a código generado por IA, y se estima que el número real es mucho mayor.Georgia Tech, vía Engadget

¿Qué es XSS (cross-site scripting)?

1 · Entrada

Un texto entra a la app

Lo escribe un usuario en un formulario o viene en un archivo importado, por ejemplo un CSV.

2 · Inserción

La app lo inserta como HTML

Con innerHTML, el navegador no lo trata como texto: interpreta etiquetas y atributos como parte de la página.

3 · Ejecución

El navegador ejecuta el código

Si el texto trae JavaScript, se ejecuta con los permisos de la app: puede leer los datos guardados, cambiar la pantalla o enviar información a otro sitio.

Corrección: insertar el texto con textContent o escaparlo antes de mostrarlo. Así el navegador lo muestra tal cual y no lo interpreta. Ejemplo: con <img src=x onerror="alert(1)">, la app vulnerable intenta cargar una imagen llamada "x"; como no existe, se dispara onerror y se ejecuta el código.

Demostración

Escribe una descripción de solicitud o usa un ejemplo. A la izquierda, la app insegura la inserta con innerHTML. A la derecha, la segura la inserta como texto con textContent.

App insegura el.innerHTML = desc

App segura el.textContent = desc

El texto se ve tal cual. Nada se interpreta ni se ejecuta.

Esta demostración corre en una caja aislada (sandbox) y no ejecuta nada. En una app real sin esa protección, el ejemplo con onerror ejecutaría código: podría leer lo que la app guarda en el navegador o cambiar lo que ve el usuario. El CSV del laboratorio incluye esta prueba en la solicitud SOL-2026-0042: si al importarlo aparece una ventana emergente, la app tiene XSS.

09
Protección de datos, antes de escribir el prompt

¿Qué puede ir en un prompt de código?

Para construir y probar una app basta con datos sintéticos que tengan la misma estructura que los reales; la IA puede generarlos. Responde estas preguntas antes de pegar información en un chat.

Verde

    Nunca en un prompt

    • Información confidencial de pacientes, clientes o de la institución, incluso si se extrajo de producción para pruebas.
    • Contraseñas, llaves de API, tokens, cadenas de conexión.
    • Datos personales de colaboradores: documento, teléfono, salario.

    Con la herramienta institucional y criterio

    • Estructuras de tablas, nombres de campos y reglas de negocio.
    • Código interno que no tenga secretos.
    • Procedimientos internos que no sean confidenciales.

    Sin problema

    • Datos sintéticos que generó la propia IA.
    • Información pública: normas, estándares, documentación oficial.
    • Tu especificación TAREA.

    El marco de referencia en Colombia es la Ley 1581 de 2012 (protección de datos personales), junto con la política de tratamiento de datos de cada institución. Ante la duda, se usan datos sintéticos.

    Madurez de una solución

    Del prototipo al producto, paso a paso

    Un prototipo HTML sirve para validar una idea con usuarios. Si funciona, avanza al siguiente nivel; cada nivel tiene una condición que se debe cumplir antes de pasar al siguiente.

    1

    Prototipo HTML con IA

    Un archivo, datos sintéticos, en tu navegador. Es lo que hacemos hoy.

    Para avanzar¿Los usuarios lo entienden y lo quieren usar? Pruébalo con 3 personas.
    2

    Herramientas institucionales sin código

    Formulario de Forms → lista de SharePoint → flujo de Power Automate con conectores estándar (aprobaciones, correo, Teams).

    Para avanzar¿Varias personas lo usan a diario? ¿Ya hay datos reales y se necesitan permisos por rol?
    3

    App de bajo código gobernada

    Power Apps u otra plataforma aprobada, con identidad institucional, permisos y auditoría.

    Para avanzar¿Debe integrarse con sistemas centrales o maneja datos clínicos o sensibles?
    4

    Desarrollo formal

    Repositorio, pruebas automáticas, revisión de código y de seguridad, despliegue controlado e interoperabilidad con estándares. Aquí los agentes de código ayudan, pero el ciclo de desarrollo manda.

    CondiciónSi maneja información confidencial o datos personales, requiere a TI, seguridad y protección de datos.

    Puente con Power Automate: la app puede exportar un CSV con las mismas columnas que una lista de SharePoint, y un flujo con conectores estándar puede encargarse de las alertas de vencimiento por correo o Teams. Pídele a la IA que describa ese flujo paso a paso y valídalo en Power Automate.

    11
    Para no perderse

    Glosario

    Vibe coding
    Programar describiendo lo que quieres en lenguaje natural y dejando que la IA escriba el código.
    App de un solo archivo
    Un HTML que tiene adentro la estructura, el estilo (CSS) y la lógica (JavaScript). No necesita servidor.
    localStorage
    Espacio del navegador donde una página guarda datos. Es local, no está cifrado y no se comparte con otros equipos.
    Criterio de aceptación
    Condición verificable que define cuándo una función está terminada.
    XSS
    Cross-site scripting: un texto con código que la app muestra como HTML y termina ejecutándose.
    Inyección de fórmulas CSV
    Celdas que empiezan con =, +, - o @ y que Excel interpreta como fórmulas al abrir el archivo.
    Slopsquatting
    Registrar con malware el nombre de una librería que las IA suelen inventar, a la espera de que alguien la instale.
    ANS (SLA)
    Acuerdo de nivel de servicio: el plazo comprometido para atender una solicitud.
    Agente de código
    IA que lee, edita y ejecuta código en un proyecto: propone cambios, corre pruebas y repite.
    Datos sintéticos
    Datos inventados con la misma forma que los reales. Permiten construir y probar sin exponer a nadie.
    FHIR
    Estándar de HL7 para intercambiar información de salud mediante recursos (Patient, Encounter…) y API web.
    Prueba de borde
    Probar con valores extremos o raros: vacío, muy largo, fechas imposibles, caracteres especiales.
